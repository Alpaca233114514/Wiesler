# 本地 DNS 检查验收版 · 2026-11-03

本轮是 Windows 桌面本地测试版。授权实测已经取得系统 DNS 事件与网卡 DNS 报文，仍在修正采集覆盖缺口；详细数据见 `desktop-feedback-20261103.md`。自动测试不代替真实 DNS 泄漏检测验收。

## 使用

1. 解压整个包，运行 `Wiesler.exe`。进入「隐私检查」。无需填写控制器或 DNS 端口。
2. 选择「DNS 应经代理 / 隧道」或「仅观察分流」，选择 30 秒或 2 分钟，点击「开始本地检查」。
3. 已有采集权限时直接开始；权限不足时自动弹出 Windows UAC，确认后自动采集，无需再次点击授权按钮。UAC 只启动本轮采集助手，主界面保持普通权限；取消后显示「已取消检查」，不会循环弹窗。
4. 观察期间正常使用需要检查的应用。查看查询域名、类型、结果、解析器、进程信息和网卡方向；可切换「物理出口证据」与「加密 DNS」。
5. 点击停止或等待到期。展开页面底部「原始报告 · JSON」，点击「生成 JSON 报告」，可复制本轮完整证据和错误。

不需要关闭系统安全功能、修改执行策略或让整个界面以管理员身份运行。包不会覆盖原有桌面程序。需要已有 Microsoft Edge WebView2 Runtime，以及支持 Packet Monitor 多会话接口的 Windows；不支持时会报出具体接口错误。

## 实际采集

- **Windows DNS 事件**：实时订阅 `Microsoft-Windows-DNS-Client`，读取查询名、类型、完成状态、返回记录、解析器、活动 ID 和进程依据。优先使用事件的 `ClientPID`；缺失时保留事件进程 PID，不把它伪装为已确认的原始应用。进程已退出或 PID 被复用时不猜进程名。
- **系统加密 DNS**：读取系统 DoH/DoT 的 8043/8044 事件，展示 Windows 提供的查询名、服务器和 PID。这是操作系统提供的事件，不是解密 HTTPS。
- **网卡报文**：通过 Packet Monitor API 创建独立会话，自动枚举物理与虚拟接口，捕获 53/853 端口相关报文。不会清空其他 PktMon 会话或全局过滤器。解析 IPv4/IPv6、UDP DNS、带长度前缀的 TCP DNS，并重组已见握手的 TCP 流。
- **短连接**：采集使用事件/报文流，不依赖图谱的一秒或三秒连接快照。隐藏窗口、冻结图谱和切换控制器不会中断本轮 DNS 采集。
- **本地处理**：数据在进程内存与本机受限通道中传输，不自动上传、不写系统配置。仅在明确导出或验收脚本指定本地报告时保存。最多保留 2,000 条普通记录，另保留最早 100 条物理出口证据；超限计数可见。

## DNS 泄漏判断

「DNS 应经代理 / 隧道」条件下，只有完整解析出的明文 DNS 查询在已识别的物理网卡 **发送方向** 被捕获，才显示「检测到明文 DNS 绕过隧道」。每条结论带查询、解析器与网卡证据；物理网卡上的响应、虚拟网卡报文、端口号、DNS 配置、ETW 接口字段或出口 IP 不单独触发这个结论。

「仅观察分流」下，相同证据显示为物理出口观察结果，不按代理要求报警。若公司内网 DNS 等直连符合你的策略，应选择此模式；当前没有按域名定制例外列表。

无记录、权限不足、捕获错误、丢包、解析缺口均不会产生“无泄漏”结论。已发现的正向泄漏证据也不会因后续丢包或普通记录滚动而消失。

## 需要你验收的部分

- Windows UAC 授权、拒绝授权和停止操作是否正常；到期或关闭程序后助手是否退出。
- 授权后两个采集来源能否接通，网卡能否正确匹配到 WLAN、以太网或隧道接口。
- 正常使用应用时，域名、响应和进程依据是否出现；短查询是否被保留。
- 在你既有的代理配置中，结果是否与实际流量相符。不要只为制造测试结果而关闭安全设置。

仍有明确限制：应用自行实现且绕过 Windows DNS 服务的 DoH/DoQ 内容不能普遍解读；853 端口只标记加密 DNS 候选。系统 DoH/DoT 事件不等于该连接的物理出口证据，当前没有把加密 DNS 绕行判定为已确认泄漏。IP 分片不重组，未见握手的 TCP 流及超大/不支持的帧记入覆盖缺口。报文与系统事件分开保留，没有仅凭相同域名强行关联进程。

## 实现与验证来源

开发前检查了 [dns-watcher](https://github.com/feiglein74/dns-watcher) 的能力范围；未复制该项目代码。原生实现依据微软的 [Packet Monitor API](https://learn.microsoft.com/windows/win32/pktmon/pktmon-reference) 和 [ETW](https://learn.microsoft.com/windows/win32/etw/event-tracing-portal) 接口。本机 Windows 事件元数据确认了使用的 DNS 字段。

本轮直接引用已存在于 lockfile 的微软 [windows-sys 0.61.2](https://github.com/microsoft/windows-rs)，许可为 MIT OR Apache-2.0；检查过包元数据，无安装构建脚本。没有增加抓包驱动或解密证书。

验证入口：`cargo test --offline --lib`、桌面三个 Node 测试文件，以及 `examples/dns-capture-smoke.rs` 的普通用户助手通信检查。真实捕获测试此前因 Windows 权限不足未通过，待用户验收。
