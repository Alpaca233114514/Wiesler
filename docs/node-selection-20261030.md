# 2026-10-30 节点选择实测与方法论

状态：本机实测记录。目标是把"选一个好节点"变成可复用、可审计的软件能力。数据采集于 2026-10-30 19:00–19:30，单机单出口，不是节点商的一般性能评测。

## 1. 结论

`🔰 节点选择` 已切到 🇨🇦 加拿大，出口核验 `loc=CA ip=187.15.154.234`。

选中它的理由只有一条：**在全部测试里零失败**。12 轮并发探测 12/12、浸泡 15/15、对比测试 25/25，三次 60MB 持续传输全部跑完。它的延迟不是最低（中位 1436 ms），但尾部最干净（最大 2839 ms）。

次优 🇨🇳 台湾01 -ANYTLS 0.8倍率 值得单列：同样 25/25，中位 878 ms、p90 1634 ms、最大 2169 ms，且按 0.8 倍计费。它只在 8 并发那一轮掉过 1 次（11/12）。如果更在意交互延迟和流量成本，它比加拿大更好；如果只认零失败记录，选加拿大。

## 2. 前置条件：外部控制器必须开

本机 `verge.yaml` 里 `enable_external_controller: false`，Mihomo 只有命名管道。非提权 shell 连该管道超时（`cvctl doctor` 报 no reachable External Controller），这与 [本轮实现记录](implementation-20261030.md) 里记的阻塞项是同一件事。

本轮做了这些本机改动：

- 备份 `verge.yaml` 为 `verge.yaml.bak-20261030-190119-pre-node-pick`。
- 把 `enable_external_controller` 设为 `true`，重启客户端；核心重启（PID 6756），`127.0.0.1:9097` 开始监听。
- 核验：`cvctl doctor` → API reachable / Authenticated true / Version v1.19.32；`unified-delay: true` 已在生成配置中。

结论性事实：**HTTP 控制器可用之后，读取 `proxies`、`/proxies/{name}/delay` 和写入组选择都不再受管道权限限制**。这解掉了之前"真实 Mihomo 验收未完成"的一半阻塞（另一半是生命周期/断流验收，见第 8 节）。

## 4. 方法：四阶段漏斗

| 阶段 | 规模 | 参数 | 目的 |
|---|---|---|---|
| 1 延迟筛查 | 76 × 1 轮 | `timeout=5000`, URL `https://chatgpt.com/cdn-cgi/trace` | 剔除不可达 |
| 2 稳定性 | 76 × 12 轮 | 8 并发，每轮轮转全部节点，`timeout=8000` | 失败率、p90、抖动 |
| 3 浸泡 | 前 5 名 | 一次 60MB 下载（上限 90 s）+ 15 次背靠背请求 | 长连接是否掉 |
| 4 对比 | 前 2 名 | 60MB + 25 次请求 + 出口 trace | 同条件决赛 |

阶段 2 用"每轮遍历所有节点"而不是"每个节点连测 12 次"，让时间与网络状况对所有节点公平；并发 8 是为了在合理时间内覆盖，代价见第 6 节第 2 条。

## 6. 方法论陷阱（这些是能力化时必须写进契约的东西）

1. **单轮延迟没有预测力**。香港 04 单轮 855 ms、12 轮中位 2019 ms（10/12）；法国 单轮 1430 ms、中位 2673 ms（10/12）。只测一轮的排序会给出错误答案。
2. **并发阶段的失败含义不明确**。马来西亚 01 在阶段 1 超时、阶段 2 却 12/12、浸泡时 0/15；瑞士阶段 2 是 12/12，浸泡 9/15 且 60MB 传输失败。同一节点在不同口径下结论相反，并发度和测量方式必须写进契约，否则失败可归因于节点，也可归因于探测方式。
3. **Windows 下 `curl -o /dev/null` 返回 exit 23**，会把每次成功的传输判成失败。必须用 `nul`（Python 的 `os.devnull`）。
4. **Mihomo 的 delay 端点在超时时返回 HTTP 504**，要映射成失败而不是异常退出；客户端超时必须长于探测超时（40 s vs 8 s）。
5. **`PUT /proxies/{group}` 是严格名字匹配**，名字写错一个汉字就返回 400 Bad Request。节点名含 emoji 和空格，必须 percent-encode（`quote(name, safe='')`）。本轮就因"加拗大" vs "加拿大" 触发过一次。
6. **切换节点会改变用户正在走的路由**。吞吐/浸泡测试必须独占进行，结束后恢复最终选择；否则度量之间互相污染。
7. **先验证路由再测速**。组选择只在规则把目标流量导向该组时才有意义，`chatgpt.com` 是走 Match 兜底才到 `🔰 节点选择` 的，不是显式规则。
8. **不要混用统一延迟和原始 curl 计时**。`unified-delay: true` 已开，delay 端点给的是统一口径毫秒数，curl 给的是墙钟秒数，混在一张表里会得出错误结论。

## 7. 能力化设计

### CLI 形态

读路径与写路径分开，写默认不生效：

```text
wiesler nodes list   --controller http://127.0.0.1:9097
wiesler nodes probe  --url https://chatgpt.com/cdn-cgi/trace --rounds 12 --workers 8 \
                     --exclude 🇭🇰 --out nodes-probe.json
wiesler nodes soak   --from nodes-probe.json --top 5 --bytes 60000000 --pings 15
wiesler nodes select --from nodes-probe.json --policy stability --dry-run
wiesler nodes select --from nodes-probe.json --policy stability --apply
```

### 度量记录

单次样本：`schema`、`measured_at`、`controller_version`、`url`、`timeout_ms`、`concurrency`、`round`、`name`、`group`、`delay_ms`
或 `error_class`（`timeout` / `tls_handshake` / `reset` / `http_5xx`）、`exit_loc`。

聚合：`ok`、`fail`、`median`、`p90`、`max`、`stdev`、`soak_bytes`、`soak_kbps`、`soak_ok`、`ping_ok`。

### 排序策略（显式、可版本化）

`policy=stability` 的固定顺序：

1. 硬淘汰：任何一次浸泡传输失败。
2. 按 `(fail_rounds, p90, median)` 升序。
3. 破平：已知倍率优先（0.8 倍优于 1 倍），再看吞吐。

决策必须连同 policy 标识、证据引用（探针输出路径或 SQLite 事件 id）和 `from → to` 一起落库，否则事后无法解释"为什么昨夜是加拿大、今夜是台湾"。

### 与现有架构的冲突点

[架构规划](architecture.md) 写死两条：不进入转发路径、不改变系统代理与路由。**节点选择本身就是对代理状态的写操作**，与只读观察的核心约束相冲突。处理方式：

- `nodes probe / soak` 归入 `src/probes/`，保持只读，不碰选择状态。
- `nodes select` 独立成显式命令，默认 `--dry-run`，绝不在检测到劣化时自动切换（那等于自动改路由）。
- 写入前记录旧值，失败可回滚；事件类型新增 `node_selection_decision`，让 `diagnose` 能引用它。

### 数据新鲜度

`probe` 必须把 profile 的 mtime 和订阅更新结果写进输出。本轮订阅自 2026-08-23 起就没更新成功过，若不显式记录，报告会看起来比实际可信。

## 8. 未验证与限制

- 单机、单 ISP、单个 30 分钟窗口（2026-10-30 19:00–19:30），不是一般性能基准。
- 目标只有 `https://chatgpt.com/cdn-cgi/trace`，没有验证 OpenAI API 可用性、模型调用、TTFT 或 TPS。
- 60MB 传输只说明带宽与握手可用，不等于模型流式输出质量。
- 没有多小时观察。19:15–19:20 之间有节点从满分翻到全灭，说明短窗口结论不能承诺长期稳定；候选节点需要跨多个窗口重复验证。
- 清单与套餐信息停留在 2026-08-23 缓存（订阅更新失败），"剩余流量/到期时间"均不可信。
- 排除香港是按要求执行，不是技术判断。
- 只观测了出口国家（CA/TW），没有评估各地区对 OpenAI 服务条款的适用性。
- 本轮改动过本机代理配置（`enable_external_controller`），备份路径见第 2 节。
- 探针脚本与原始数据在工作区外：`C:\Users\Logan\codex-node-probe\`（`stable.py`、`soak.py`、`confirm.py`、`stable.json`、`soak.json`、`confirm.json`），未纳入本仓库。经由代理的实际测试流量约 300MB，全部为 60MB 级传输。
